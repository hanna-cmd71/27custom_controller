## 1. 为什么 URDF 能直接推固件要的 DH

固件里 `terminal_dh_transform()` 的乘积是

```
T = R(axis, θ+offset) · Trans(a,0,d) · Rx(α)
```

`axis = (0,0,1)` 时就是**经典（distal / 教科书）DH**：

```
T = Rz(θ)·Tz(d)·Tx(a)·Rx(α)         展开矩阵是
                                     [[cθ, -sθcα,  sθsα, a·cθ],
                                      [sθ,  cθcα, -cθsα, a·sθ],
                                      [0,   sα,    cα,   d   ]]
```

**它不是 Craig 的改进 DH（MDH）**。两者是两个不同的变换，表不能通用：

| | 经典 DH（本固件现在就是这种） | Craig MDH |
|---|---|---|
| 乘积 | `Rz(θ)·Tz(d)·Tx(a)·Rx(α)` | `Rx(α)·Tx(a)·Rz(θ)·Tz(d)` |
| 平移列 | `(a·cθ, a·sθ, d)` | `(a, -sα·d, cα·d)` |
| frame i 的 z 轴 | 关节 **i+1** 的轴 | 关节 **i** 的轴 |
| `x_i` 垂直于 | `(z_{i-1}, z_i)` | `(z_i, z_{i+1})` |
| `a` / `α` 属于 | 第 i 根连杆（本行） | 第 i-1 根连杆（上一行） |
| 表列顺序习惯 | θ, d, a, α | α, a, θ, d |

两套表在数值上看着只差"挪一行"：**MDH 的 `a/α` 就是经典 DH 的 `a/α` 往上挪一行**（并且把
`base_transform` 的平移和第 0 行的扭角吃进 MDH 第 0 行）。但乘积的因子顺序不同，混用会直接崩：

```
同一份 URDF、200 组随机关节角，末端 4×4 的最大元素误差
  经典表 × 经典乘积   1.19e-15 m    ← 本固件（§3.2 那张表）
  MDH 表  × MDH 乘积  1.24e-15 m    ← §9 那张表
  经典表 × MDH 乘积   1.97e+00 m    ← 混用的后果
  MDH 表  × 经典乘积  1.99e+00 m    ← 混用的后果
```

数来自 `_check\verify_dh_vs_mdh.py`（可重跑）。

> 关于 `doc/MDH_Parameters_Tutorial.md`：那份文档**自相矛盾**——坐标系规则（`X_i = Z_i×Z_{i+1}`）
> 和 4×4 展开矩阵（平移列 `(a, -sα·d, cα·d)`）都是 Craig MDH 的写法，乘积行却写成了经典 DH 的顺序。
> 所以它不能直接当规格用。本固件按**乘积行**实现（经典 DH），本文 §3 的表也是按经典 DH 推的；
> 要 Craig MDH 的表看 §9，附录里有那份文档哪几行能用的逐条判定。

## 2. 推导方法

URDF 给的是"关节轴 + 连杆坐标系"，DH 要的是"公垂线 + 扭角"，中间那步转换全靠坐标系的定义：

1. **关节轴**：`Z_i` = 关节 i+1 的转轴（URDF 的 `axis` 写在子关节系里，先换算到 base 系）。
2. **公垂线**：`X_i` = `Z_{i-1} × Z_i` 归一化（⟂ `Z_{i-1}` 与 `Z_i` 两根轴——这是**经典 DH** 的指派，
   MDH 会取 `Z_i × Z_{i+1}`，见 §1 的表）；`O_i` = `Z_{i-1}` 与 `Z_i` 的公垂线在 `Z_i` 上的垂足。
   四种退化情形：
   - 两轴重合：原点任取、X 任取（本机构没出现）；
   - 两轴相交：`O_i` 取交点；
   - 两轴平行：`O_i` 取 `O_{i-1}` 在 `Z_i` 上的垂足，`X_i` 取 `O_{i-1} → O_i` 的方向；
   - 两轴异面：`O_i` 取公垂线与 `Z_i` 的交点。
3. **参数**（第 i 行 = frame i-1 → frame i，`Q_i` 是公垂线在 `Z_{i-1}` 上的垂足）：
   `θ_i` = `X_{i-1}` 到 `X_i` 绕 `Z_{i-1}` 的角、`d_i` = `Q_i − O_{i-1}` 在 `Z_{i-1}` 上的投影、
   `a_i` = `O_i − Q_i` 在 `X_i` 上的投影、`α_i` = `Z_{i-1}` 到 `Z_i` 绕 `X_i` 的角。
   零位（q=0）时 `θ_i` 剩下的常数就是 `.offset`。
4. **链的起点不是 `base_link`**：DH 的 `frame0` 取在 J1 轴线上（原点 = J1 关节原点），
   `base_link` 到它的平移进 `base_transform`。搞错这一步正解会整体差 64 mm。

**必须在 URDF 零位（所有关节 = 0）推导。** 平行判定的容差要放到 `1e-6` 以上：同一对平行轴
在不同位形下会有 `1e-7` 量级的数值差，容差取 1e-9 会误进"异面"分支，公垂线方向就成噪声了
（这句话是踩过坑写下来的）。

## 3. 结果

### 3.1 base_transform（frame0 相对 base_link，**单位 mm**）

```
{1, 0, 0,  0.4023300}
{0, 1, 0,  0.0000000}
{0, 0, 1, 64.0000000}
{0, 0, 0,  1.0000000}
```

`frame0` 的原点就是 URDF 里 Joint1 的 `origin xyz`：`(0.40233, 0, 64) mm`。
**注意单位**：URDF 里是米（`0.00040233 / 0.064`），固件全程 mm，写成米就整体差 1000 倍。

|---|---|---|---|---|---|---|
| 0 | J1 | -0.8914 | 47.0001 | 1.570796 (90°) | -3.141593 (-180°) | `X1 = Z1×Z2` 落在 -x，零位差半圈 |
| 1 | J2 | 99.9740 | 0.0000 | 0 (0°) | +0.010012 (+0.574°) | 大臂绕 J2 的装配偏角（CAD 里两轴并不严格正交） |
| 2 | J3 | -0.8884 | 14.1315 | 1.570796 (90°) | -1.580804 (-90.573°) | 小臂折回 90° + 上一条的同源偏角 |
| 3 | J4 | 0.3320 | 95.6620 | 1.570796 (90°) | 0 | — |

`axis` 六个全部填 `{0,0,1}`；转角信息全在 `.offset` 里，这样 `terminal_dh_transform` 就退化成

J0 的 `-π` 和 J2 的 `-90.573°` 看着吓人，但都是有物理含义的值（不是"截断出来的 -3.14"）：
`-3.141593` 与 `-M_PI` 差 `3e-7`。

### 3.3 末端法兰的固定偏置（正解输出的是 frame6，不是法兰）

第 6 行 DH 的 `a=d=0`，所以 `frame6` 原点 = 腕心，法兰还在它前方 86.19 mm：

```
pose_Link6 = pose_frame6 · C,   C = diag(-1, 1, -1)，平移 (0, 0, -86.1869) mm
```

即法兰原点在 `frame6` 的 **-z 方向 86.187 mm** 处，坐标系绕 z 转 180°。做末端轨迹/标定时
记得补这一层；只做重力补偿用不到它。

## 4. 质量与质心（换成 DH 系）

## 5. 校验数据

* DH 正解 vs URDF 正解：300 组随机位姿，末端位置最大差 **3.87e-3 mm**、旋转元最大差 **2.34e-5**
  （来源是 `.a/.d` 只保留 4 位小数、`alpha` 取 `1.570796`，可以忽略）。
* 质心随位姿一致性（同一质心在 DH 系里推回 base 系）：**2.2e-13 mm**。
* 重力力矩（g = 9.8，2000 组随机位姿的峰值）：`(0, 0.725, 0.318, 0.088, 0.088, 0)` N·m。
  J0 恒 0 是因为 J1 轴竖直（回转关节不受重力矩），J5 恒≈0 是因为腕部自转轴与质心几乎共线。
* **一个容易看走眼的巧合**：`q=0` 与 `q=[0,-45°,+45°]` 两姿态的 J2 力矩都是 -0.3176 N·m。
  这不是 bug：两平行轴按 `θ` 和 `-θ` 复合是纯平移，小臂及之后整段相对 J2 轴的几何没变。

## 7. 怎么重跑

```powershell
# 1) 推参数（URDF 路径写在脚本顶部，改机构时改那一行）
python _check\urdf_dh.py
#    可选：把 6 个关节方向符号当参数传给脚本（电机方向与 URDF 不一致时用）
python _check\urdf_dh.py 1 -1 1 1 1 1

```

`urdf_dh.py` 直接打印可粘贴的 C 代码（DH 表、base、mass、com）。`verify_firmware_dh.py`
是把固件里**已经写进去的数**抄一遍再和 URDF 比，所以它是"验证落盘值"的，不是"再推一遍"。

## 8. 局限 / 实机复核清单

CAD 是名义值，实机有公差和装配偏差；做完零位标定（`doc/calibration_and_validation.md` 的 S4）
后按这几条核对一遍：

1. **连杆长度**：卡尺量 J1 轴到 J2 轴的竖直距离（应 47.00 mm）、J2/J3 两平行轴间距（应 99.97 mm）。
   误差 > 0.5 mm 就按实测改 `.a/.d`。
2. **零位姿态**：摆在 §6 的姿态，`joint_fb` 应全为 0 ± 0.002 rad；再转到 q3 = +90°，
   `joint_fb[2]` 应 1.571 ± 0.005。
3. **法兰坐标**：用 §6 的表对一对（卷尺/卡尺，5 mm 以内算过）。
4. **质量**：称一下六段连杆的实际重量（合计应约 0.655 kg）。CAD 值是按体积×密度算的，
   实心铝件一般差 5~10%；差 20% 以上要按实测改 `LINK_MASS`，否则重力补偿会欠/过补偿。
5. **质心**：不拆机就只能信 CAD；拆得动的话用"两点悬挂法"校 1~2 段。
6. 上面任一项改了，重跑 §7 的 `verify_firmware_dh.py`，别只改一处。

> 单位约定（固件全链路）：长度 mm，角度 rad，力矩 N·m，质量 kg。URDF 的长度是 m，
> 脚本里 `dh_T()` 会 `/1000` 转成 m 去和 URDF 对拍，而打印出来的 C 代码已经是 mm。

## 9. 如果哪天要换成 Craig MDH

§3 的表**只对固件现在这个乘积（经典 DH）成立**。如果要把 `terminal_dh_transform()` 改成 Craig 的
`T = Rx(α)·Tx(a)·Rz(θ)·Tz(d)`（很多教材/论文写的是这一种），表必须换成下面这张。同一份 URDF
推的，同样在 200 组随机关节角上和 URDF 正解对拍到 `1.2e-15`：

```c
/* T = Rx(alpha) * Tx(a) * Rz(theta + offset) * Tz(d) */
/* J1 */ {.a =   0.4023f, .d =  111.0001f, .alpha = 0.000000f, .offset = -3.141585f}
/* J2 */ {.a =  -0.8914f, .d =  -41.2763f, .alpha = 1.570793f, .offset =  0.010012f}
/* J3 */ {.a =  99.9740f, .d =   55.4078f, .alpha = 0.000000f, .offset = -1.580804f}
/* J4 */ {.a =  -0.8884f, .d =   95.6620f, .alpha = 1.570793f, .offset =  0.000004f}
/* J5 */ {.a =   0.3320f, .d =   -5.2923f, .alpha = 1.570796f, .offset =  0.000000f}
/* J6 */ {.a =  -1.0521f, .d =  -86.1870f, .alpha = 1.570800f, .offset =  3.141593f}
```

`base_transform` 在 MDH 下是**单位阵**（frame0 直接取 URDF 的 `base_link`）。

> 行号约定：本节按"第 j 行 ↔ 关节 j+1"排，frame i 的 `z` = 关节 i 的轴（所以 `a/α` 挂在
> 前一行的连杆上）。若你手上的教材把 frame i 的 `z` 定义成关节 i+1 的轴，那张表整体
> **往下挪一行**才对得上，数值本身不变。

一眼能看出的"挪一行"关系：

| | 经典 DH（§3.2） | Craig MDH（本节） |
|---|---|---|
| 第 0 行 | `a=-0.89, d=47.00, α=90°` | `a=0.40, d=111.00, α=0°` ← 吸收掉 base 的 64 mm 与 0.402 mm |
| 第 1 行 | `a=99.97, d=0, α=0°` | `a=-0.89, d=-41.28, α=90°` |
| 第 2 行 | `a=-0.89, d=14.13, α=90°` | `a=99.97, d=55.41, α=0°` |
| 第 3 行 | `a=0.33, d=95.66, α=90°` | `a=-0.89, d=95.66, α=90°` |
| 第 4 行 | `a=-1.05, d=-5.29, α=90°` | `a=0.33, d=-5.29, α=90°` |
| 第 5 行 | `a=0, d=0, α=0` | `a=-1.05, d=-86.19, α=90°` |

末端也不一样：MDH 的 frame6 正好落在 URDF 的 `Link6` 原点（法兰）上，末端固定变换 `C = diag(1,-1,-1)`、
平移 0；经典 DH 那边 frame6 还在腕心，`C` 要再走 `-86.187 mm`（§3.3）。**换约定时这三处
（乘积、表、base/C）必须一起换，换一半就是上表里那 1.97 m 的误差。**

重跑：

```powershell
python _check\urdf_mdh.py        # 打印这张 MDH 表
python _check\verify_dh_vs_mdh.py  # 四种"表 × 乘积"组合的对拍
```

## 附：`MDH_Parameters_Tutorial.md` 哪几行能用

| 教程里的东西 | 判定 |
|---|---|
| 标题 "MDH"、坐标系规则 `X_i = Z_i × Z_{i+1}` | Craig MDH 的指派方式，自洽 |
| 4×4 展开矩阵（平移列 `(a, -sα·d, cα·d)`） | Craig MDH 的正确矩阵，与 `Rx·Tx·Rz·Tz` 配套 |
| 乘积行 `Rot_z(θ_i)·Trans_z(d_i)·Trans_x(a_{i-1})·Rot_x(α_{i-1})` | **经典 DH 的顺序**，与上面两行矛盾；照它算出来的表和那个矩阵不配套 |
| `a_{i-1}` / `α_{i-1}`（挂前一根连杆）的下标 | MDH 的叫法；同一个量在经典 DH 里叫 `a_i` / `α_i`（差一行） |

所以：

- 用**本固件**（乘积是经典 DH）：照 §3.2 填，**不要**照抄教程的 4×4 矩阵；
- 想要**教程标题那种 MDH**：照 §9 的表填，并且把 `terminal_dh_transform` 的乘积改成
  `Rx(α)·Tx(a)·Rz(θ)·Tz(d)`、`base_transform` 改单位阵。
